## 3. Q1 — what the sandbox API's `cost` field represents

**What the sources say**
- API reference, `resources.cost`: type `number<float>`, description "Operation cost"; `elapsed_time`: "Elapsed wall time". No unit, currency or
  formula. https://docs.tokenfactory.nebius.com/api-reference/sandboxes/operations/get-an-operation-status (embedded OpenAPI schema, path
  `metadata.oneOf.0.result.resources.cost`) [direct]. The "Result of one subprocess" page shows the same two descriptions [fetch].
- Same operation schema also has `consumed_cpu` ("CPU seconds (user_cpu_time + system_cpu_time) reported by the in-VM init"), `consumed_memory`
  (peak `max_rss`), `image_size` ("Bytes written for the resulting image/layer(s)"), `duration` [direct]. No page says `cost` is computed from them.
- SDK `contree-sdk` 0.3.6 passes the number through untouched, no docstring, no unit: `.../contree_sdk/sdk/objects/image_like/result.py:19`
  (`cost: float = field(repr=False)`), `:39` (`cost=raw_result.result.resources.cost`); `.../_internals/models/instance.py:11-12`
  (`cost: float`, `elapsed_time: float` in `ProcessResources`). The package README has no mention of cost, billing, credits or price.
  Import operations have no cost field in the SDK model (`.../_internals/models/operation.py:16-23`), so any import cost is not in our ledger.
- "USD" is **our** wording, not Nebius's: `backend/app/services/sandbox.py:27` ("`ContreeResult.cost` (a float, USD)"), `:452` (`cost_usd=result.cost`).
- MCP docs: a "Cost" column with `run` and `import_image` = "VM" and all else "Free" (cheatsheet) / "Spawns microVM" vs "No VM" (tools reference)
  [direct]. That classifies who spawns a VM; it states no price, unit or "billable".
- No Sandboxes pricing page exists in the docs index (https://docs.tokenfactory.nebius.com/llms.txt, 241 lines, read [direct]); the console price
  page https://tokenfactory.nebius.com/organization/prices answers "Log in to continue" (not read).

**What the records show (facts only; gate v1.4.0 records, `operations[]` and `install_seconds[]`/`rerun_steps[]`, `runs/corpus_v2_batch/harness-v1.4.0/gate/*.json`)**
- Cost tracks API `elapsed_time` (our `sandbox_seconds`), not client wall time: #07 op 1 cost $0.0027 for 0.22 sandbox-s in 81.3 s wall.
- Steps >= 3 s (n=21): cost / seconds min $0.01005/s, median $0.01013/s, max $0.01454/s; 18 of 21 lie in $0.01005-$0.01039/s. The two highest
  are the 20.2 s and 20.6 s baseline `pip install torch ...` steps ($0.01369, $0.01454/s). Operations >= 3 s, no estimate (n=15): min 0.01007,
  median 0.01021, max 0.01147, pooled sum(cost)/sum(seconds) = $0.01027/s. Implied about **$36-37 per sandbox-hour**.
- Short steps are higher per second: 0.03-0.04 s branch overlays $0.0115-0.0123/s; 0.2 s extract steps $0.0111-0.0118/s; 0.001 s `true`
  steps cost $0.000051-$0.000062 each (#03, #08, #11; #07's carries the folded extract cost). Seal records (6 decimals): 1.072794 s -> $0.0117993 (0.01100/s); 0.073076 s -> $0.000812 (0.01111/s); 0.012053 s ->
  $0.00016935 (0.01405/s). So `cost` is close to, but **not exactly**, a constant $/s; a small per-operation floor is consistent with this, not proven.
- Same level two days earlier: `runs/torch_check/*.json` (2026-09-29), steps >= 1 s (n=7): min 0.01008, median 0.01039, max 0.01248, pooled
  $0.01033/s. No change of rate between 09-29 and 10-01, so no sign of a price change.
- The cost guard's `SANDBOX_COST_RATE_USD_PER_S = 0.0085` (`cost_guard.py:60`, derived over client wall seconds) is below the per-sandbox-second
  ratio of all 21 steps >= 3 s (min 0.01005). The killed-step ESTIMATES (22.0 s x 0.0085 = $0.1868 on #08 op 11) are therefore below the API
  ratio. Side fact for D-27; out of scope here.
- `cost` is non-zero on every operation although the product page (Q2) says beta runs are free: it is a metering value or list price, not
  proof of a charge.
- Kept-image test: reopening a kept image after 600 s cost $0.00017036 vs $0.00054618 for the first run (`SEAL_STATUS.md:22`): no storage
  term in a run's `cost`. That says nothing about storage on the account bill.
- For scale only (a different product, not shown to apply): Nebius Compute list price "Non-GPU Intel Ice Lake. CPU $0.012 per 1 CPU hour"
  (https://docs.nebius.com/compute/resources/pricing [direct]). The sandbox VM size is undocumented, so no conclusion follows.

**What is not established**: unit and currency of `cost`; list price vs charged amount; formula (time only, or CPU / memory / I/O); per step vs
per run (the API returns it per operation result; our records sum steps); whether imports and storage are metered anywhere; whether the value is
what the account is debited (Q2 suggests not during beta).

## 4. Q2 — is Sandboxes (beta) billed at all?

**What the sources say**
- https://tokenfactory.nebius.com/sandboxes/about (redirect of /sandboxes, logged out, with a "Sandboxes Beta" label) [direct]: "Free while in
  beta — runs don't consume your credits." The playground text on the same page says "free while in beta".
- https://contree.dev FAQ [direct, embedded FAQ data]: "Sandboxes is currently in beta." and "Authentication, billing, and quotas are managed
  through Token Factory". Also: "Access tokens are issued through Nebius Token Factory".
- https://docs.tokenfactory.nebius.com/sandboxes/overview [direct]: "Sandboxes are currently in Beta." Beta limits: 50 simultaneous operations,
  "Checkpoint images retention is set to 180 days." No pricing sentence anywhere on the page.
- https://docs.tokenfactory.nebius.com/other-capabilities/billing-new [direct]: no occurrence of "sandbox", "delay", "lag" or "hours".
- Our earlier note: `SEAL_STATUS.md:6,23` and `METHODOLOGY.md:933`: "docs list only run and import_image as billable". Verified: that is the
  cheatsheet "Cost" column (VM vs Free) quoted above. The word "billable" and the reading "VM = charged" are our interpretation; the same docs set
  carries the statement above that beta runs are free, which that note did not cite.

**What is not established**: whether the "free" line is current and applies to this organisation (marketing page, undated, read logged out);
what the console shows after login; whether "don't consume your credits" also means no card/deposit charge; what happens after the beta.

**What the sources say**

  days." (so the owner's $50.00 is not the sign-up trial); "A promo code provides free Nebius Token Factory credits"; "You can verify this in the
  Transactions section."; "Nebius Token Factory debits your balance in real time." (sentence sits under "When using a bank card");
  "You can monitor spending across projects, services, and resources on the Usage tab" (Organisation page; filters region, project, service, product).
- No Token Factory page found states a usage or balance display delay. Inference is the product's core service and the page speaks of one
  balance, but no sentence lists "inference" or "sandboxes" per service.
- Nebius Builder Program terms https://nebius.com/builders-terms-and-conditions [direct]: "USD $25 in Nebius Token Factory credits", plus
  "USD $25 in Tavily partner credits"; credits "expire 90 days from the date of issuance". Whether the owner's $50.00 comes from this is not
  stated in the repository (grep of all .md: no statement; `CHANGELOG.md:167` only says "$21.76 of $25").
- Archived ToS https://docs.tokenfactory.nebius.com/legal/archive/terms-of-service-20251104 [fetch]: "The Service is provided on a pre-paid basis."
  Archived version, may not be current.
- Different product (Nebius AI Cloud docs, console.nebius.com): "Resource usage and its costs are tracked in real time by your PAYG balance"
  (https://docs.nebius.com/signup-billing/billing-models/payg [fetch]); "Budget usage data updates every few hours"
  (https://docs.nebius.com/signup-billing/budgets [fetch]); usage export "once per hour" (.../usage/export [fetch]). Applicability to Token Factory unknown.

**Arithmetic for the owner's window (section 2)**: model $ alone is $1.4972 over all records, $0.8217 since 2026-09-30 00:00 UTC, $0.4245 in the
ledger window, $0.2550 on 2026-10-01. The charged $0.39 is below the first two, 8% below the third, above the fourth. If sandboxes are free in
beta and the balance is real time, the $50.00 pool would have started about 2026-09-30 21:06 UTC, or model prices differ from the charge. If the
balance lags, the latest usage is missing. None of this is decidable from the repository.
