## 4. Estimated cost of a v1.4.0 gate under "install once, branch per attempt"

Everything in this section is ESTIMATED; the inputs are MEASURED or DERIVED and named. Per entry:

`entry = A + B + n x R + model`
- **A**, the as-published baseline operation: its recorded cost in v1.3.4 (operation 1).
- **B**, the checkpoint build (era lock + dependency install + first re-execution, run non-disposable, giving `env_image_id`): the recorded cost of operation 2 in v1.3.4; for #08, whose operation 2 was killed, the completed operation 2 of v1.3.3.
- **R**, one branch run from `env_image_id` (apply one candidate, smoke run of at most 60 s). **No record measures this**; it is the number the seal has to produce. Two bounds:
  - R-low = $0.0011 [MEASURED, `smoke_exits_ok_py310.json`.cost_usd]: the dearest smoke run on a ready image in the v1.3.4 seal (commands that do almost no work).
  - R-high, per entry = the entry's dearest re-execution minus the seal-measured torch chain. It still contains the non-torch installs and the repository download, which a branch does not repeat, so it is an upper bound. For #07 (no torch; its repairs were environment changes) no saving is assumed: R-high is its dearest repair operation.
- **n**: "same sequence" = the re-executions v1.3.4 actually made after operation 2; "at cap" = 12 [DERIVED: 3 candidates x 3 rounds + 3 non-disposable runs of the adjudicated winner].
- **model**: "same sequence" = the entry's recorded model spend; "at cap" = the entry's non-repair calls as recorded + 9 candidates + 3 Ultra adjudications, a candidate priced at the mean $0.0067 (low) or the maximum $0.0177 (high) of the 22 recorded repairer calls, an adjudication at $0.0077 [ESTIMATED: 3 x the dearest recorded Ultra call $0.0026, for three diffs in the prompt].

## 5. Owner decisions on this note (2026-10-01), recorded as annotations

Accepted corrections (the records win; the directive's wording is kept beside them, never edited in place):
- "Three of the four v1.3.4 gate losses" reads **two of four** were install-bound (#08, #11); #03 is the silent exit (D-25), #07 had no torch (finding 1).

Decisions:
1. The ceiling is a **seal + gate cap**, not a ledger ceiling. Proposed shape: seal at most $1.50 [ESTIMATED: owner's proposal], gate at most $5.00 with an entry cap of
   $1.25 each [ESTIMATED: owner's proposal], so gate >= 4 x entry and no entry inherits a starved cap. The figure is the owner's to write in chat; nothing live starts before it.
2. Criterion (e) reads: **torch installed at most once per environment image**, checkable from the records; the planner-image baseline install is counted separately and is outside (e).
3. Step 1 (offline, `harness-v1.4.0-rc`) starts now, ordered by entry: #11 CPU shim + checkpoint persistence; #08 checkpoint persistence + a fixed entry cap; #07 D-24 (already in);
   #03 the D-25 exit-site hook; then the parallel-candidate repair (3 x 3 cap).
