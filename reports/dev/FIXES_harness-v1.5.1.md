## What each fix does

- **F1.** After `python_policy.resolve_from_repo`, the repo's torch pin (read from its dependency files as the runner already reads it) is looked up in a dated snapshot of the PyTorch CPU
  wheel index (`torch_wheels_data.py`, generated by `scripts/build_torch_wheel_table.py` from `https://download.pytorch.org/whl/cpu/torch/`, retrieved 2026-10-02). If the chosen Python has no
  wheel for any release satisfying the pin, the interpreter follows the pin: the policy's most preferred Python that has one. A pin the chosen Python can install, no pin, or a pin
  nothing in the snapshot satisfies changes nothing. The reason is logged (`[python] ... (torch pin): ...`) and kept in the plan notes.
- **F2.** Before any model call (the same place as D-24's build-essential rule), a failing run whose log contains a signature in `api_removals.RULES` gets one deterministic step:
  the package is pinned to the one release that still has the API (`torch==1.8.1`, `tensorflow==1.15.5` with `protobuf==3.20.3`, or `3.19.6` on Python 3.6, unless the requirements already
  pin it) and, if the current Python cannot install it, the Python moves to one that can (3.9, 3.7); the command runs again. If the changed environment fails in RERUN's own setup step, or
  the budget stops it, the build plan is put back as it was and the model repairs the original failure. The same env gate a model proposal faces checks the change (the matched log text is the evidence, verbatim); the step is recorded as attempt 0 /
  origin `time_machine` with `time_machine_action`; it fires once per rule per run and never moves the Python under an era lock compiled for another interpreter.
- **F3.** The CPU shim makes `torch.cuda.set_device(...)` do nothing (and records the path `cuda.set_device`); the classifier reads `module 'torch._C' has no attribute '_cuda_*'` as
  GPU_REQUIRED, so the shim is installed deterministically after the baseline instead of being reached by accident through a candidate.

## Not fixed in this round, and why (so that nothing is hidden)

- **#5** (INDETERMINATE DEP_UNPINNED_CONFLICT): the runner's own command was `pip install torch==1.2.0 torchvision==0.5.0 torchaudio ...`: the repository's requirements pin a torch/torchvision
  pair that cannot coexist (torchvision 0.5.0 needs torch 1.4.0) and the runner's fallback repeats the same pins. Class "mutually inconsistent torch-family pins": one entry; relaxing the
  companion pins would also change what a baseline success means (it would have to be labelled a repair), so it is not done blind. Open.
- **#14**: after the shim, `LU without pivoting is not implemented on the CPU` (`torch.lu` on a CPU tensor): a CUDA-only operation. Open (a repository limit on this runner).
- **#16**: apt 404s on `security.debian.org` for `python:3.6-slim` (Debian 11 is end-of-life): one entry shows it; not fixed.
- **#4**: the documented command has unsubstituted placeholders (`[model_path]`, `original.png`) and needs files that are not in the repository: a legitimate BLOCKED.
- **#15** reached RUNS_AFTER_REPAIR by the model's removal of a `dataclasses` pin and is `smoke_alive` (unconfirmed). A deterministic rule for it has a recorded failure but its class
  (a stdlib backport pinned at a version the interpreter excludes) is covered by no other record, so no rule was added.
